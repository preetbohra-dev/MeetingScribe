Meeting Tracker · on-device

MeetingScribe

Zero-touch Microsoft Teams meeting notes. It notices when you join a call, records it, and when you hang up writes a Markdown note with a summary, action items and a speaker-labelled transcript. All of it runs on your Mac. Nothing goes online.

🍎 Apple Silicon · macOS 14.4+ 🔒 100% offline after model download 🗣️ Whisper large-v3-turbo 🧠 Qwen 2.5 14B (MLX) 👥 Voice-based speaker ID 🚫 No admin, no audio drivers

Features

What you get without ever pressing record.

⚡

Automatic start and stop

Detects when Teams takes the microphone and starts recording. Stops shortly after you leave the call.

🎧

Two clean tracks

Your mic is "Me". Teams' own audio output is everyone else. Captured with a private Core Audio tap, with no screen-recording glow.

📝

Accurate transcription

mlx-whisper on the GPU, per track. Long silences are skipped first so Whisper doesn't invent text.

👥

Who said what

Remote voices are told apart by voice fingerprint and matched to people it has heard before.

🧹

Work-only notes

A local LLM drops small talk and personal chat before anything is written.

✅

Summary and action items

Qwen 2.5 14B writes a summary and a checklist of action items with owners.

🏷️

Smart titles

Notes are named after the Teams meeting window title (optional permission).

🛟

Crash-safe

Raw audio is kept until processing succeeds. A crash or power loss mid-call is processed on next start.

🔒

Private by design

Models load from disk with offline flags set. Ollama is only allowed on 127.0.0.1.

How it works

A background daemon watches Teams. A low-priority sub-process turns each recording into a note.

During the call
1

Detect every 1 s

Core Audio exposes every audio process as a process object. When a com.microsoft.teams2.* process holds the mic for start_after_s, recording begins.

2

Record mic.pcm + system.pcm

Microphone via sounddevice. Teams audio via a Core Audio process tap on the Teams processes only. You keep hearing the meeting normally.

3

Stop

Teams releases the mic for stop_after_s → recording ends. If you're muted, an open meeting window keeps it alive for up to 10 minutes.

After the call
4

Transcribe

Energy-gate silence, then mlx-whisper on each track. Lines that look like echo of the remote side are tagged.

5

Identify speakers

ECAPA voice embeddings → cluster remote voices → match against your voiceprint library.

6

Merge and filter

Both tracks merged by timestamp. The work-only filter removes non-work lines.

7

Summarize and write

Qwen 2.5 14B (mlx-lm or local Ollama) writes summary and action items. Markdown saved to ~/Documents/Meeting Notes/.

💻

Apple Silicon Mac

💾

Disk

About 8 GB for models, plus about 230 MB per meeting hour while processing.

🐍

Python 3.12 – 3.14

Setup

About 15 minutes, most of it model download.

Create the Python environment

cd ~/Desktop/"AdHoc Developments"/"Meeting Tracker"
/opt/homebrew/bin/python3.14 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt

No Homebrew? uv installs into your home folder without admin:

curl -LsSf https://astral.sh/uv/install.sh | sh
uv venv -p 3.12 .venv
uv pip install -p .venv -r requirements.txt

Download the models

The only step that uses the network.

.venv/bin/python meeting_scribe.py download-models

After this every run sets HF_HUB_OFFLINE=1, so models load from disk only.

Optional: use Ollama instead of mlx-lm

Set llm_backend = "ollama" in config.toml, then:

brew services start ollama   # listens on 127.0.0.1:11434 only
ollama pull qwen2.5:14b

Any Ollama URL that isn't loopback is refused.

Daily use

Nothing to do. Join Teams calls as usual. For control, use ctl.sh.

Speakers and notes

./ctl.sh listen ["Speaker 2"]Play ~10 s clips of unknown voices in the latest meeting.

Retry a failed session

Raw audio is kept until processing succeeds, so you can rerun it:

.venv/bin/python meeting_scribe.py process ~/Library/Application\ Support/MeetingScribe/sessions/<id>
All meeting_scribe.py sub-commands
  • run background daemon (launched by the app)
  • process DIR transcribe → merge → summarize → write Markdown
  • status permissions, Teams audio state, detected windows
  • test-capture N record N seconds of both tracks and report levels
  • download-models one-time model download
  • name-speaker, listen, voices, refilter (wrapped by ctl.sh)

Identifying speakers

All remote people arrive in one stream, so they are told apart by voice.

1

Fingerprint

Every 1 s, a 2 s slice of speech becomes a 192-number ECAPA-TDNN embedding, on-device.

2

Cluster

Similar slices group into one speaker. Near-duplicate clusters merge; tiny ones fold into the closest voice.

3

Assign

Each sentence goes to the speaker who owns most of it.

4

Match

Each speaker is checked against voices.json. Match → stored name. No match → Speaker 1, Speaker 2…

Teaching it names

New voices are marked (unrecognized) and listed in an Unrecognized voices table with their first lines. Not sure who it is? Listen, then name:

./ctl.sh listen                                  # clip of each unknown voice, latest meeting
./ctl.sh name "Speaker 2" "Priya Shah"           # latest meeting
./ctl.sh name "Speaker 1" "Tom Berg" 2026-10-28  # a specific meeting (session id or date)

The note is rewritten and the voiceprint saved. From the next meeting on, that person is labelled automatically, and each confident match refines the voiceprint.

Fixing mistakes
  • Wrong person? ./ctl.sh name "Wrong" "Right", then voices --forget "Wrong" if polluted.
  • One person split in two? Name both labels the same. They merge.
  • Shared meeting-room mic? Still separated, by voice.
Tuning
  • speaker_cluster_threshold 0.6 — lower if two people merge.
  • speaker_match_threshold 0.5 — similarity to reuse a name.
  • speaker_merge_similarity 0.7, speaker_min_seconds 15, max_speakers 0 — clean up fragments.
  • speaker_id = false — label everyone "Others".
MeasuredOn synthetic voices, the same voice scored 0.83–0.90 against its voiceprint; different voices never scored above 0.51. Real Teams audio is noisier, so expect lower scores.

Work-only filter

On by default (work_only = true). Personal chat never reaches the note.

🗑️ Dropped

Weekends, holidays, family, health, food, sports, weather, jokes, chit-chat while waiting for people to join, greetings and goodbyes.

✅ Kept

All work discussion, meeting logistics ("can you see my screen"), and short replies ("yes", "okay") to work points.

Two passes, one model

Qwen 2.5 14B (same model as the summary, loaded once) first lists candidate lines in numbered batches. Each candidate is then rechecked with the three lines around it and dropped only if it's clearly a greeting/goodbye or personal small talk. If unsure, it keeps the line. If a batch answer can't be parsed, the whole batch is kept.

Why Qwen, not Llama?Llama 3.1 8B was tried first but dropped terse work lines like "What did the DBS say?". Qwen 2.5 14B classified all 23 hand-labelled test lines correctly.
Removed lines can't be recoveredOnly the count is logged. With keep_audio = true the WAV still holds the full call.

Older meetings

./ctl.sh refilter                              # all unfiltered meetings
./ctl.sh refilter --session 2026-11-03_0832    # one meeting
./ctl.sh refilter --force                      # redo already filtered ones

This rewrites transcript.json and the note, summary included, so hand edits are overwritten. Use a different filter model with work_filter_model; turn it all off with work_only = false.

Transcript quality

Apart from the work-only filter, nothing is deleted. Suspect lines are kept and tagged (and logged in process.log):

TagMeaning
(possible echo of the remote side)On speakers your mic also hears the others. A mic line overlapping and matching a remote line gets this tag.
(low confidence)Whisper wasn't sure.
(possible mis-hearing)A typical Whisper noise phrase ("Thank you.", "Thanks for watching").

Set drop_suspect_lines = true to delete them instead. Long silences are skipped before Whisper, with 1 s padding around anything that sounds like speech.

Privacy

📁

Local storage only

Audio goes to ~/Library/Application Support/MeetingScribe/ and is deleted after processing (unless keep_audio).

🧮

Local compute

Whisper and LLM on the GPU via MLX (or Ollama on 127.0.0.1). Voice embeddings on CPU via PyTorch.

📴

Offline flags

HF_HUB_OFFLINE, TRANSFORMERS_OFFLINE, HF_HUB_DISABLE_TELEMETRY set before any ML import.

🔍

Check it yourself

nettop -p $(pgrep -f "meeting_scribe.py process") during processing shows no connections.

Consent and biometricsMany places and employers require everyone to agree to being recorded. Voiceprints (192 numbers per person in voices.json) can't rebuild audio but are biometric data (e.g. GDPR, Illinois BIPA). Check company policy and tell participants.

Built-in robustness

  • Switching headsets mid-call restarts mic capture.
  • If the Teams-only tap stays silent while Teams plays audio, it falls back to all system audio.
  • Hung Core Audio calls can't freeze the daemon — streams close with a timeout.
  • Crash or power loss keeps the raw PCM; it's processed on next start.
